# 팀 클라우드 오토: 실시간 공동 편집 설계

## 왜 만드나

팀 25341 팀원들이 같은 오토를 여러 노트북에서 **구글 문서처럼 동시에** 고친다.
한 사람이 고친 내용은 다른 사람 화면에 바로 보인다. 오토는 클라우드 목록에
모여 있고, 목록에서 골라 열어 수정한다.

## 목표

- 같은 오토를 여러 명이 동시에 고쳐도 각자의 수정이 모두 남는다. 서로 다른
  점, 경로, 대기 시간, 액션을 고치면 전부 합쳐진다.
- 클라우드 오토 목록을 보여 주고, 열기, 새로 만들기, 이름 바꾸기, 삭제를 할 수 있다.
- 지금 열려 있는 (로컬) 프로젝트를 클라우드 오토로 올릴 수 있다.
- 팀 비밀번호를 아는 사람만 목록을 보고, 열고, 고칠 수 있다.
- 같은 오토를 보고 있는 팀원의 이름을 화면에 보여 준다.
- 연결이 끊겨도 계속 고칠 수 있고, 다시 연결되면 합쳐진다.

## 하지 않는 것

- 다른 사람 마우스 커서나 선택 표시. 이름 목록만 보여 준다.
- 팀원별 계정과 권한. 비밀번호 하나로 모두 같은 권한을 가진다.
- 버전 기록과 되돌리기 화면. 실행 취소는 내 수정만 되돌린다(아래).
- 설정(로봇 이미지, 필드 배경, 테마 등) 공유. 각자 브라우저 설정이다.
- GitHub Pages 사이트. 서버 함수가 없어서 클라우드 기능은 Vercel 사이트에서만 된다.

## 실패로 보는 것

- 한 사람의 수정이 조용히 사라지는 것. 같은 값을 동시에 바꾼 경우만 예외다.
  예를 들어 같은 점을 동시에 끌면 마지막 사람 것이 남는다.
- 실행 취소를 눌렀더니 다른 사람의 수정까지 되돌아가는 것.
- 비밀번호 없이 오토를 보거나 지울 수 있는 것.
- 비밀 키가 브라우저 코드에 들어가는 것.

## 방식 (사용자가 A를 골랐다)

- **A. Liveblocks + Yjs (선택).**
  - Yjs는 자동 병합(CRDT) 문서다. 문서의 칸 단위로 동시 수정을 합친다.
  - Liveblocks는 Yjs 문서를 호스팅하고 실시간으로 중계해 준다. 무료 요금제로 충분하다.
  - 구글 문서처럼 동작하는 유일한 방식이라 골랐다.
- **B. Firebase.** 경로 단위로 마지막 저장이 이긴다. 같은 경로를 동시에 고치면
  한쪽이 사라진다.
- **탈락: 파일 통째로 주고받기.** 동시에 고치면 한쪽 작업이 통째로 사라진다.

## 구조

### 문서 연결 (핵심, `src/cloud/binding.ts`)

이 앱의 `ProjectDoc`은 바뀌지 않는 객체다. 수정할 때마다 새 객체로 바뀐다
(`ProjectStore.apply`). 그래서 연결 코드는 다음처럼 동작한다.

- **로컬 → 클라우드:**
  - `project.doc`가 바뀌면 이전 문서와 새 문서를 비교한다.
  - 바뀐 부분만 Y 문서에 쓴다. 하나의 트랜잭션으로 쓰고, 출처는 "local"이다.
- **클라우드 → 로컬:**
  - 다른 사람의 변경이 오면 Y 문서 전체를 JSON으로 바꾼다.
  - `project.replaceFromCloud(doc)`로 화면에 넣는다. 이때 실행 취소 기록에는 넣지 않는다.
- **변환 규칙** (JSON ↔ Y):
  - 객체는 `Y.Map`이 된다.
  - 숫자, 문자열, 불리언, null은 값 그대로다.
  - 배열 원소가 전부 `id`를 가진 객체면(경로, 장애물, 액션, 순서 항목) `Y.Array`로 두고 **id로 비교**한다.
    - 삭제된 id는 지운다.
    - 새 id는 그 위치에 넣는다.
    - 같은 id는 안쪽만 비교한다.
    - 순서가 바뀐 원소는 지우고 다시 넣는다.
  - 그 밖의 배열(제어점처럼 id 없는 것)은 `Y.Array`로 두고 **위치로 비교**한다.
    - 같은 위치끼리는 안쪽을 비교한다.
    - 길이가 달라진 만큼 끝에서 넣거나 지운다.
  - 값이 `undefined`인 키는 지운다. `actions`, `hardware`가 없는 파일이 그대로 남게 하려는 것이다.
- **드래그 중:** `preview`로 바뀌는 중간 상태도 바로 보낸다. 다른 사람이 끌리는
  점을 실시간으로 본다.
- **드래그 중에 남의 수정이 들어올 때:**
  - 드래그를 Esc로 취소하면 내 드래그만 되돌린다.
  - 그 사이 들어온 남의 수정은 남는다(`Y.UndoManager`로 되돌린다).

### 실행 취소

- 클라우드 오토를 열면 실행 취소와 다시 실행을 `Y.UndoManager`가 맡는다.
  "local" 출처만 추적하므로 내 수정만 되돌린다.
- 한 번의 드래그나 한 번의 입력은 실행 취소 한 번으로 되돌린다.
  - 기존 `commit`과 `coalesce`에 맞춰 `stopCapturing()`을 부른다.
  - 1초 안의 연속 입력은 하나로 묶는다. 기존 `COALESCE_MS`와 같다.
- 로컬 파일을 열면 지금 방식 그대로다.

### 클라우드 오토 목록

- 오토 하나는 Liveblocks 방 하나다. 방 id는 `auto-<무작위>`다.
- 이름은 방 메타데이터 `name`에 둔다. 이름을 바꿔도 링크가 유지된다.
- 화면:
  - File 메뉴 → **Cloud autos…** 대화상자를 연다.
    - 목록: 이름, 마지막 수정 시각.
    - 버튼: 열기, 새로 만들기, 이름 바꾸기, 삭제(확인 창을 띄운다).
    - **Upload current**: 지금 프로젝트로 새 오토를 만든다.
  - 클라우드 오토를 열면 상단 바 파일 이름 자리에 표시가 나온다.
    - 예: `☁ 오토1 · 연결됨 · 민수, 지호`
    - 연결이 끊기면 `다시 연결 중…`이 된다.
- 주소에 `?auto=<방 id>`가 붙는다. 그 링크를 팀원에게 보내면 같은 오토가 열린다.
- 클라우드 오토에는 "저장"이 없다. 항상 저장된 상태다.
  - Save는 지금처럼 .pp 파일로 내려받기만 한다(백업용).
  - Export와 Send to robot은 그대로 동작한다.
- 클라우드 오토를 열고 있을 때 로컬 파일을 열거나 New를 누르면 방에서 나간다.

### 서버 (Vercel 함수, `api/`)

비밀 키는 Vercel 환경 변수에만 둔다: `LIVEBLOCKS_SECRET_KEY`, `TEAM_PASSWORD`.

- `POST /api/liveblocks-auth`
  - 받는 값: `{ password, name, room }`
  - 비밀번호가 맞으면 `auto-*` 방에 쓰기 권한이 있는 토큰을 준다. 이름도 함께 담는다.
  - 틀리면 401을 돌려준다.
- `/api/autos`
  - 요청 헤더 `x-team-password`로 비밀번호를 확인한다.
  - `GET`: 목록.
  - `POST {name, doc?}`: 새 방을 만든다. `doc`이 있으면 그 내용으로 시작한다.
  - `PATCH {id, name}`: 이름을 바꾼다.
  - `DELETE {id}`: 삭제한다.
- 새 방의 첫 내용은 서버가 넣는다.
  - `POST /api/autos`가 받은 `doc`을 연결 코드(브라우저와 같은 `src/cloud/binding.ts`)로 Y 업데이트로 바꾼다.
  - 그 업데이트를 방을 만들면서 같이 넣는다.
  - 그래서 처음 들어온 두 사람이 동시에 첫 내용을 쓰는 경쟁이 없다.
  - 새로 만들기는 브라우저가 기본 프로젝트를 `doc`으로 보낸다.

### 브라우저 쪽 설정

- 비밀번호와 이름은 처음 한 번 묻고 `localStorage`에 둔다.
- 비밀번호가 틀리면 다시 묻는다.
- Liveblocks 공개 키는 필요 없다. 토큰은 `authEndpoint` 함수로 받는다.

## 정해진 것과 내가 정한 것

- **사용자가 정한 것:**
  - 구글 문서처럼 실시간으로 동시에 반영한다.
  - Liveblocks + Yjs로 만든다.
  - 클라우드 목록에서 골라 수정한다.
- **내가 정한 것** (고칠 수 있다):
  - 접근 방식: 팀 비밀번호 하나.
  - 다른 사람 표시: 이름 목록만 보여 준다.
  - 주소에 방 id를 붙인다.
  - 실행 취소는 내 것만 되돌린다.
  - 설정은 공유하지 않는다.
  - GitHub Pages는 지원하지 않는다.

## 확인 방법

- **연결 코드 단위 테스트:** 서버 없이 Y 문서 두 개를 메모리에서 서로 동기화한다.
  - 한쪽 수정이 다른 쪽 `ProjectDoc`에 똑같이 나타난다.
  - 두 쪽이 서로 다른 점이나 경로를 동시에 고치면 둘 다 남는다.
  - 경로 추가, 삭제, 순서 변경, 제어점 추가와 삭제가 맞게 합쳐진다.
  - 실행 취소는 내 수정만 되돌린다.
  - 모든 예제 프로젝트를 Y로 바꿨다가 되돌리면 원래와 똑같다.
- **서버 함수 테스트:** 비밀번호가 틀리면 401이다. Liveblocks 호출은 가짜로 대신한다.
- **e2e:** Cloud autos 대화상자의 목록, 열기, 삭제 흐름을 서버 응답을 가짜로 만들어 확인한다.
- **실제 확인:** 사용자가 Liveblocks 키와 비밀번호를 Vercel에 넣은 뒤, 브라우저 창 두 개로 확인한다.

## 사용자가 해야 하는 일

1. liveblocks.io에 가입하고 프로젝트를 만든 뒤, **Secret key**를 복사한다.
2. Vercel 프로젝트 → Settings → Environment Variables에 `LIVEBLOCKS_SECRET_KEY`와
   `TEAM_PASSWORD`를 넣는다.
3. 다시 배포한다.

## 빌더에게 맡기는 것

- 대화상자 모양과 문구. 기존 다이얼로그 스타일을 따른다.
- 패키지 버전. 2주 이상 된 정확한 버전을 쓴다.
- 연결 상태 표시의 세부.
